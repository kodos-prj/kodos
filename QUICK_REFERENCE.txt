ENTRY POINT:
  kod.py → Click CLI framework with commands:
    • install     - Full install workflow (empty baseline)
    • rebuild     - Rebuild with current generation or new generation
    • plan        - Preview execution plan
    • config      - Subcommands for validation, compilation, schema, init
    • registry    - Subcommands for program management
    • rebuild_user - Rebuild user dotfiles/scripts
    • shell       - Run shell with schroot

CORE WORKFLOW (INSTALL):
  1. Load config (kod.config.loader) → Python dict
  2. Validate (kod.config.validator) → Lua schema
  3. Compile (kod.config.compiler) → Resolve dependencies
  4. Build plan (kod.planner.build_plan) → List of Steps
  5. Execute (kod.executor.execute_steps) → Lua runner
  6. Record state (kod.system.packages.store_packages_services)

CORE WORKFLOW (REBUILD):
  1. Load current state (/.generation, /kod/generations/N/)
  2. Load config & compile (same as install)
  3. Build diff plan (kod.planner.plan_rebuild) against current state
  4. Execute plan (same as install)
  5. Finalize generation (move, update fstab, write /.generation)

DESIGN PATTERNS:
  • Singleton:       LuaRuntimeManager (prevents runtime mixing)
  • Strategy:        distro.factory (runtime distro selection)
  • Immutable:       Step (frozen dataclass, converted to_dict for Lua)
  • Re-export Hub:   kod.core (clean API, consolidates system operations)
  • Hook Pattern:    collect_hooks before exec, fire during steps
  • Error Aggregate: validator collects all errors, reports once

WORKFLOW STAGES:
  • install       Creates generation 0 from empty baseline
  • rebuild       Updates current generation or creates new generation N
  • plan          Preview (read-only, no execution, matches actual behavior)
  • rebuild_user  Updates user dotfiles/scripts without full rebuild
