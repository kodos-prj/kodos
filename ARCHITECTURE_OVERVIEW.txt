PROBLEM ANALYSIS
════════════════════════════════════════════════════════════════════════════════

Priority 1: PYTHON STRUCTURE
  Current:  core.py (2,038 lines) handles install, rebuild, users, packages, boot
  Issue:    No clear boundaries; hard to test; hard to understand
  Solution: Split by responsibility → 6-8 focused modules (~200-400 lines each)

Priority 2: RUNTIME PERFORMANCE
  Current:  Install errors caught 4 hours in (config validation during execution)
  Issue:    Wasted time debugging "what went wrong?"
  Solution: Compilation phase → validate config upfront (seconds, not hours)

Priority 3: CONFIG COMPLEXITY
  Current:  One configuration.lua (~300 lines); program configs as Lua functions
  Issue:    No module system; no schema; hard to extend
  Solution: NixOS-style modular imports, schema, plugin-based program registry

CONFIGURATION SYSTEM
════════════════════════════════════════════════════════════════════════════════

BEFORE (Current):
  ┌─ configuration.lua (300 lines in one file)
  └─ All options flat, no module system

AFTER (Proposed):
  ┌─ configuration.lua (entry point, ~50 lines)
  │   ├─ imports = ["modules/base", "modules/desktop", "modules/users"]
  │   └─ config = { hostname = "myvm", ... }
  │
  ├─ modules/base/default.lua
  │   └─ config = { boot.kernel = "linux-lts", ... }
  │
  ├─ modules/desktop/gnome.lua
  │   └─ config = { desktop.gnome.enable = true, ... }
  │
  └─ modules/users/demo/default.lua
      └─ config = { users.demo = { name = "Demo", ... } }

COMPILE PHASE:
  1. Load    → Parse Lua, resolve imports
  2. Compile → Flatten structure, auto-enable dependencies (GNOME→gdm)
  3. Validate→ Type-check against schema
  ✓ Ready to install (or errors caught in seconds)


PYTHON REFACTORING
════════════════════════════════════════════════════════════════════════════════

BEFORE: 
  core.py (2,038 lines)
  ├─ Install logic
  ├─ Rebuild logic
  ├─ User config logic
  ├─ Package management
  ├─ Service management
  ├─ User creation
  ├─ Boot setup
  └─ Filesystem setup
  
  → Hard to find code, hard to test, high cognitive load

AFTER:
  kod/
  ├─ core/
  │   ├─ install.py      (~150 lines) ← Install workflow
  │   ├─ rebuild.py      (~150 lines) ← Rebuild workflow
  │   └─ user_config.py  (~100 lines) ← User config workflow
  │
  ├─ system/
  │   ├─ packages.py     (~100 lines) ← Package operations
  │   ├─ services.py     (~80 lines)  ← Service operations
  │   ├─ users.py        (~120 lines) ← User operations
  │   ├─ boot.py         (~150 lines) ← Boot operations
  │   └─ filesystem.py   (existing, moved)
  │
  └─ distributions/
      ├─ base.py         (~50 lines)  ← Abstract interface
      ├─ arch.py         (refactored) ← Arch implementation
      └─ debian.py       (refactored) ← Debian implementation

  → Each file ~100-200 lines, one responsibility, testable in isolation


PROGRAM REGISTRY
════════════════════════════════════════════════════════════════════════════════

BEFORE:
  config.git() → Lua helper function (users must know it exists)

AFTER:
  kod/registry/programs.py
  ├─ "git"      → { packages, options, config_generator }
  ├─ "neovim"   → { packages, options, config_generator }
  ├─ "syncthing"→ { packages, options, config_generator }
  └─ ... more

  Plugin System:
  ~/.kod/plugins/programs/myapp.py
  └─ PROGRAM_DEFINITION = { "myapp" → { packages, options, config_generator } }
     (Auto-discovered, merged into registry)

  Usage:
  programs = {
    git = { enable = true, user_name = "...", user_email = "..." },
    myapp = { enable = true, custom_option = "value" },
  }


ERROR HANDLING
════════════════════════════════════════════════════════════════════════════════

BEFORE:
  Global `problems` list (fragile, hidden errors)
  Dead exception classes (never raised)

AFTER:
  KodError (base)
  ├─ ConfigError     → Config parsing/validation failed
  ├─ CommandError    → System command failed
  └─ DistributionError → Distribution-specific operation failed

  Errors are traceable, testable, recoverable

DATA FLOW
════════════════════════════════════════════════════════════════════════════════

Install Workflow:

  1. User runs: kod install -c example/testvm

  2. Load Phase (config/loader.py)
     config.lua → Lua parser → raw config dict

  3. Compile Phase (config/compiler.py)
     raw config → resolve imports → flatten structure → auto-enable deps

  4. Validate Phase (config/validator.py)
     compiled config → check types, enums, constraints → validated config
     
     ⚡ Errors caught HERE (before touching system)

  5. Execute Phase (core/install.py)
     validated config → get distribution → setup filesystems → install packages
                    → configure boot, services, users → store generation

  6. Done
     System installed, generation metadata stored
